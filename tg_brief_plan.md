# tg_brief — план разработки MVP

## 0. Цель MVP

Сделать Telegram-бота-интерфейс, который работает вместе с Telegram user-client.

Пользовательский сценарий:

1. Открыть бота.
2. Получить список доступных Telegram-чатов / групп / каналов из личного аккаунта.
3. Выбрать нужный чат.
4. Выбрать режим:
   - суммировать все непрочитанные;
   - последние 100 сообщений;
   - последние 500 сообщений;
   - последние 1000 сообщений.
5. Получить AI-summary.
6. В summary видеть основные темы и ссылки на важные оригинальные сообщения.

---

## Смена подхода (2026-08-09)

Изначальный план (Node.js + TypeScript + TDLib с нуля) заменён на **форк готового проекта**
[Telebrief](https://github.com/belaytzev/Telebrief) вместо билда с нуля — он уже закрывает
большую часть инфраструктуры.

Причины:
- TDLib на Windows требует нативной сборки (`tdjson.dll`) — болезненно в установке.
- Библиотека `teleproto` (альтернатива GramJS) при аудите оказалась соло-мейнтейнер форком без
  прозрачной истории — решили не рисковать сессией личного аккаунта.
- Telebrief уже реализует user-client (Telethon) + Telegram bot (python-telegram-bot) + AI-саммари
  с темами и ссылками на оригинальные сообщения — то есть почти весь стек из разделов 1–9 старого
  плана, только на Python вместо Node/TS.

Код Telebrief **вендорен локально** в этот репозиторий (не через `git fork` на GitHub — здесь нет
настроенного `gh`/токена). Если понадобится push в собственный GitHub-репозиторий или синхронизация
с апстримом, форкнуть вручную через https://github.com/belaytzev/Telebrief/fork и добавить как
`upstream` remote.

Лицензия: MIT (сохранена, файл `LICENSE` в репозитории).

## 2. Чего в Telebrief нет и что нужно доделать (адаптация под наш сценарий)

Telebrief рассчитан на **статический список каналов** в `config.yaml` и дайджест по времени
(`lookback_hours`), с командами `/digest`, `/status`, `/cleanup`. Нашему сценарию (раздел 0) нужно
другое:

1. **Динамический список чатов вместо статичного config.yaml**
   Добавить метод в `MessageCollector` (или новый модуль), который вызывает
   `client.get_dialogs()` и возвращает список чатов личного аккаунта с `id`, `title`, `type`,
   `unread_count` — это раздел 5 старого плана (шаги 3–4).

2. **Inline-кнопки выбора чата и режима**
   Новый flow в `bot_commands.py` (или отдельный `src/chat_picker.py`):
   `/start` → кнопки со списком чатов (title + unread) → выбор чата → кнопки режима
   (`Все непрочитанные` / `Последние 100` / `Последние 500` / `Последние 1000`) → генерация.
   Соответствует разделу 8 старого плана. Технически — `CallbackQueryHandler` из
   `python-telegram-bot` с `callback_data` вида `chat:<id>` / `mode:<n>`.

3. **Fetch по количеству и по непрочитанным, а не по времени**
   `fetch_channel_messages` в `collector.py` сейчас работает через `lookback_hours`. Нужно добавить
   режимы:
   - `last N` — `client.iter_messages(entity, limit=N)`;
   - `unread` — прочитать `dialog.unread_count` из `get_dialogs()` и взять именно столько последних
     сообщений (без пометки "прочитано" — как и требовал раздел 6 старого плана).

4. **Саммари по одному выбранному чату "на лету"**
   Сейчас `summarizer.py`/`grouper.py` работают над структурой "канал → сообщения" из конфига.
   Нужно прогнать через них результат fetch для одного произвольного чата, выбранного в рантайме
   (а не из `config.yaml`).

Форматирование вывода (топики + ссылки на сообщения, раздел 9 старого плана) уже покрыто
`formatter.py` — адаптировать по мелочи под "один чат" вместо "несколько каналов".

Scheduled-дайджест по `config.yaml` (родная фича Telebrief) можно оставить как есть — она не мешает
и может пригодиться отдельно.

### Принятые решения

- **Большие выборки.** Один вызов модели, пока текст влезает в `single_call_chars`
  (200K символов ≈ 80K токенов). 1000 обычных сообщений почти всегда влезают. Выше — части по
  200K, из каждой заметки, потом итоговое саммари. Это и дешевле, и качественнее, чем резать
  на части всегда: суммарный вход тот же, но модель видит весь контекст сразу.
- **Ссылки не отправляются в модель.** Сообщения помечаются `#id`, модель цитирует `[#id]`,
  бот сам превращает их в ссылки. Экономит примерно 35 символов на сообщение и не даёт модели
  выдумать URL.
- **Модель.** `chat_summary.ai_model: gpt-5-mini` ($0.25 / 1M вход, $2.00 / 1M выход).
  Оценка: ≈ $0.01 за 100 сообщений, ≈ $0.02–0.03 за 1000. На маленьких порциях основная цена —
  ответ модели, а он почти одинаковый для 100 и 1000, поэтому крупные порции в 3–4 раза выгоднее.
  `gpt-5-nano` ($0.05 / $0.40) примерно в 5 раз дешевле: ≈ $0.002 за 100 сообщений,
  ≈ $0.004 за 1000 (оценка). Решено переходить на неё после сравнения качества.
- **Непрочитанные (изменено 2026-09-24).** Раньше читались без пометки и брались самые новые.
  Теперь: с первого непрочитанного, порцией N, и после доставки саммари отмечаются прочитанными
  до последнего просмотренного сообщения (служебные тоже), без подтверждения. Если модель или
  Telegram упали — счётчик не трогается. В личных чатах собеседник видит «прочитано».
  `max_id=0` в Telethon означает «весь чат», поэтому такой вызов запрещён.
- **«Последние N»** — самые свежие сообщения, прочитанные или нет; счётчик не меняется.
- **Лимиты.** `max_messages` (по умолчанию 1000, потолок 5000) ограничивает размер порции
  во всех режимах.
- **Один Telegram-клиент за раз.** Все обращения к аккаунту идут через общий lock
  (`src/telegram_session.py`), чтобы не повредить файл сессии.

#### Монетизация — черновик-ориентир (2026-09-24)

Не план к реализации, а ориентир того, к чему идём.

**Модель: предоплаченный баланс.**
- Пользователь пополняет баланс фиксированной суммой: $5 / $10 / $20 / $50.
- 10% суммы — наша комиссия за сервис, 90% — баланс на саммари.
- Саммари списываются с баланса не по реальным токенам, а по прайсу с наценкой
  (оценочный принцип): так пользователь заранее знает цену, а мы не зависим от колебаний токенов.
- Разница между прайсом и реальной ценой токенов окупает сервер, деплой и поддержку.

**Формула цены саммари.**

Реальная цена одного саммари почти линейна по числу сообщений `N`:

```
cost(N) ≈ A + B · N
A ≈ $0.0016  — ответ модели (≈ 4K выходных токенов с рассуждениями × $0.40 / 1M), почти не зависит от N
B ≈ $0.0000024 за сообщение — вход (≈ 47 токенов на сообщение × $0.05 / 1M)
```

Цена для пользователя: `price(N) = k · cost(N)`, округлённая вверх до «красивой» цифры,
`k ≈ 2.5` (пример: реальные $0.002 → прайс $0.005).

| Кнопка | Реальная цена (nano, оценка) | Прайс при k ≈ 2.5 |
|---|---|---|
| 100 сообщений | ≈ $0.002 | $0.005 |
| 500 сообщений | ≈ $0.003 | $0.008 |
| 1000 сообщений | ≈ $0.004 | $0.012 |

`A` и `B` — оценки; перед запуском пересчитать по реальному логу токенов (см. «Дальше»).
Map-reduce (больше ~200K символов) стоит примерно вдвое дороже, считать отдельно.

**Счётчик баланса у пользователя.**
- `/balance`: остаток, сколько потрачено за месяц, сколько саммари примерно осталось.
- Перед запуском саммари на кнопке или в статусе: «≈ $0.005».
- Если баланса не хватает — бот не запускает саммари и предлагает пополнить.
- История списаний: дата, чат, режим, N, списано. Храним в БД (`src/storage.py` уже есть).
- Внутри для себя: реальная цена каждого саммари по `usage` из ответа модели, чтобы видеть
  фактическую маржу и корректировать `k`.

**Экономика и риски (посчитано 2026-09-24, перепроверить перед запуском).**
- Масштаб помогает: сервер — фиксированная цена, маржа на каждом саммари положительная,
  поэтому с ростом числа пользователей доля сервера падает. На 10 пользователях — минус.
- **Оплата внутри Telegram.** Цифровые товары в ботах — только через Telegram Stars.
  С учётом комиссий Apple/Google и Telegram до нас доходит примерно 50–65% оплаты
  (≈ $0.013 за Star), вывод в TON через Fragment, первый вывод через 21 день.
  Это съедает и 10% комиссию, и большую часть наценки — модель нужно считать уже после Stars.
- **Саммари слишком дешёвые для предоплаты.** Активный пользователь (≈ 5 саммари в день)
  тратит ≈ $1 прайса в месяц: пополнения $10 ему хватит почти на год. Выручка на
  пользователя поэтому маленькая. Альтернатива для сравнения — фиксированная подписка
  ($3–5 в месяц с лимитом), как у аналогов (TelyAI $5–20 в месяц, Junction Bot €5 в месяц).
- **Доверие и право.** Сервис получает полный доступ к Telegram-аккаунту пользователя
  (сессия на нашем сервере) и читает переписки третьих лиц — барьер для конверсии и вопрос GDPR.
- **Конкуренция самого Telegram.** С 2026 года Telegram сам делает AI-саммари длинных постов
  в каналах (на Cocoon). Чатов и групп это пока не касается, но может.
